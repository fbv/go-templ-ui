# i18n — Locale, Strings and Formats

`view/i18n` carries the locale a page renders in: its language tag, its string
catalog, month and weekday names, and its number/date/currency formats. A locale
travels in a `context.Context` — the one channel every templ component already
receives — so a consumer selects a locale once and every component below it
renders in that locale. No component gains a locale prop and no existing props
struct changes.

English is the built-in default. Russian ships as the second built-in locale and
doubles as the template for a locale of your own.

## Import

```go
import "github.com/fbv/go-templ-ui/view/i18n"
```

## Props

None. This is a package, not a component: the locale is carried in
`context.Context`, so there is no props struct to change and no component takes
a locale argument.

## Usage

### API reference

| Function | Description |
|----------|-------------|
| `WithLocale(ctx, l *Locale) context.Context` | Returns a context carrying `l`. A `nil` locale leaves the context unchanged. |
| `From(ctx) *Locale` | The locale carried by `ctx`; `Default()` when the context carries none or carries a locale with an empty `Tag` (a `nil` context is safe). |
| `Default() *Locale` | The locale registered under the fallback tag `"en"`. Registering a locale under that tag replaces the built-in English here too. |
| `Get(tag string) (*Locale, bool)` | The registered locale for a tag; `false` for an unknown or empty tag. |
| `Register(l *Locale) error` | Adds (or replaces) a locale keyed by its tag. Callable from a consumer's `init`. A `nil` locale or an empty tag is an error and leaves the registry untouched. |
| `T(ctx, key string, args ...any) string` | The catalog entry for `key`, formatted with `args` (`fmt.Sprintf`). |

Variables and methods:

| Identifier | Description |
|------------|-------------|
| `English *Locale` | The built-in default locale (tag `"en"`). |
| `Russian *Locale` | The built-in second locale (tag `"ru"`). |
| `(*Locale).Lookup(key string) (string, bool)` | The catalog entry for `key`; `false` when the catalog has no entry or the entry is empty. |
| `Key*` constants | Stable keys for the starter catalog (`KeyYes`, `KeyNo`, `KeyClose`, `KeyLoading`, `KeyToday`, `KeyAllDay`, `KeyNoEvents`, `KeyNoData`, `KeyCancel`, `KeyConfirm`, `KeySubmit`, `KeySearch`, `KeyTheme`, `KeyCollapse`, `KeyNew`, `KeyLogout`, `KeySelectedCount`, `KeyPageOf`, `KeyChooseDay`, `KeyMore`, `KeyEventsCalendar`, `KeyToggleSidebar`, `KeyUserAvatar`, `KeyToggleTheme`, `KeyVsPreviousPeriod`, `KeyError`, `KeyWarning`, `KeySuccess`, `KeyInfo`). Their wording is in the starter catalog table below. |

`T` resolution order: the selected locale's catalog → `Default()`'s catalog →
the key itself. A missing key therefore surfaces as the key (a visible gap) and
never as a blank or a panic. The "never empty" guarantee covers non-empty keys;
`T(ctx, "")` returns `""`.

A `Locale` is a plain value:

| Field | Meaning |
|-------|---------|
| `Tag`, `Name` | BCP 47 tag (registry key, document `lang`) and a human-readable name. |
| `Strings` | `map[string]string` catalog keyed by the `Key*` constants, or consumer keys. |
| `Months[12]` | Full month names, January first. |
| `Weekdays[7]` | Short weekday names, Monday first. |
| `Numbers` | Decimal and group separators, group size, percent spacing, currency table. |
| `DateLayout`, `DateTimeLayout`, `TimeLayout` | Go reference-time layouts. |
| `MonthYearLayout` | Optional layout for `MonthYear`; empty means month name then year. |

`Numbers` is a `NumberFormat`:

| Field | Meaning |
|-------|---------|
| `Decimal` | Fraction separator (`"."`/`","`). Empty means `"."`. |
| `Group` | Digit-group separator (`","`/`" "`). Empty means no grouping. |
| `GroupSize` | Digits per group. Zero means 3. |
| `PercentSpace` | Put a space between a percentage and `%`. |
| `Currency` | `map[string]CurrencyFormat` keyed by ISO code. A code absent from the map falls back to the code as a prefix symbol. |

`CurrencyFormat` describes one currency:

| Field | Meaning |
|-------|---------|
| `Symbol` | What replaces the code in output, e.g. `"$"`, `"€"`, `"₽"`. |
| `Position` | `"before"` (prefix) or `"after"` (suffix); anything else acts as `"before"`. |
| `Space` | Put a space between the number and the symbol. |
| `Decimals` | Fraction digits; zero means the default of 2, a negative value counts as zero. |

### Formats

Every helper reads the locale carried by `ctx`; none takes a layout or format
argument, so the same call renders per locale.

| Function | English (`en`) | Russian (`ru`) |
|----------|----------------|----------------|
| `Number(ctx, 1234567.891, 2)` | `1,234,567.89` | `1 234 567,89` |
| `Currency(ctx, 1234.5, "USD")` | `$1,234.50` | `$1 234,50` |
| `Currency(ctx, 1234.5, "RUB")` | `₽1,234.50` | `1 234,50 ₽` |
| `Currency(ctx, -12.345, "USD")` | `-$12.35` | `-$12,35` |
| `Currency(ctx, -12.345, "RUB")` | `-₽12.35` | `-12,35 ₽` |
| `Currency(ctx, math.Inf(-1), "USD")` | `-$Inf` | `-$Inf` |
| `Currency(ctx, math.NaN(), "USD")` | `$NaN` | `$NaN` |
| `Currency(ctx, math.Inf(1), "USD")` | `$+Inf` | `$+Inf` |
| `Currency(ctx, 1234.5, "CHF")` (unknown code) | `CHF 1,234.50` | `CHF 1 234,50` |
| `Percent(ctx, 12.5, 1)` | `12.5%` | `12,5%` |
| `Date(ctx, 2026-03-09)` | `03/09/2026` | `09.03.2026` |
| `DateTime(ctx, 2026-03-09 14:05)` | `03/09/2026 14:05` | `09.03.2026 14:05` |
| `Time(ctx, 2026-03-09 14:05)` | `14:05` | `14:05` |
| `MonthName(ctx, time.March)` | `March` | `Март` |
| `WeekdayName(ctx, time.Monday)` | `Mon` | `Пн` |
| `MonthYear(ctx, 2026-03-09)` | `March 2026` | `Март 2026` |

Behaviour worth knowing:

- `Number`'s `decimals` argument counts fraction digits; `0` trims the fraction
  and a negative value counts as `0`. `NaN`, `+Inf` and `-Inf` render verbatim
  with no grouping.
- `Currency` fraction digits come from `CurrencyFormat.Decimals` (zero means the
  default of 2, a negative value counts as zero). A code absent from the
  locale's currency table falls back to the code itself as the symbol. A
  negative sign is always the outermost character, including for non-finite
  amounts (`-$1,234.50`, `-$Inf`); `NaN` and `+Inf` render verbatim inside the
  symbol (`$NaN`, `$+Inf`).
- `Percent` inserts a space before `%` when `NumberFormat.PercentSpace` is set;
  both built-in locales leave it unset.
- `MonthName`/`WeekdayName` fall back to `Default()`'s name when the locale
  leaves an entry empty. `MonthName` returns `""` for an out-of-range month
  instead of panicking.
- `MonthYear` uses `Locale.MonthYearLayout` when set, otherwise the month name
  followed by the year. Go layouts expand month names in English, so leave
  `MonthYearLayout` empty when the locale's own month names should appear.
- `WeekdayName` takes a `time.Weekday` (`time.Sunday` is `0`) and maps it onto the
  locale's Monday-first weekday names.
- `.` separates the fraction and nothing groups digits when a locale leaves its
  `Numbers` zero-valued; the layouts fall back to `2006-01-02`,
  `2006-01-02 15:04` and `15:04`.

### Selecting a locale through the router

The repo renders through Fiber, and fasthttp's `RequestCtx` is the templ
context, so a wrapper is where the locale joins the chain. This is the tested
form (`view/render_test.go`):

```go
page := templ.ComponentFunc(func(ctx context.Context, w io.Writer) error {
	return demo.Render(i18n.WithLocale(ctx, i18n.Russian), w)
})
view.Render(c, page)
```

Inside any component's templ file the context is already named `ctx`, so a
string resolves with:

```go
<span>{ i18n.T(ctx, i18n.KeyNoEvents) }</span>
```

Formats are read the same way:

```go
i18n.Currency(ctx, 1234.5, "RUB")   // 1 234,50 ₽ under ru
i18n.Date(ctx, time.Date(2026, time.March, 9, 0, 0, 0, 0, time.UTC)) // 09.03.2026 under ru
```

Without a carried locale, `From(ctx)` returns `Default()` (English), so existing
pages keep working unchanged:

```go
ui.YesNo(true)                              // Yes
i18n.T(context.Background(), i18n.KeyYes)   // Yes
```

`layout.Page` sets the document language from the locale, so a Russian context
renders `<html lang="ru">` and the default context `<html lang="en">`.

### The showcase's Russian demo

`/showcase/i18n` is this exact wiring, demonstrated end to end: `I18nDemoPage`
in `showcase/i18n.go` wraps its page in the `templ.ComponentFunc` above with
`i18n.WithLocale(ctx, i18n.Russian)`, so the response carries
`<html lang="ru">` while every other showcase page keeps `<html lang="en">`.
The page renders migrated components (sidebar, alerts, toast, stat, calendars,
theme toggle) and these `ru` format samples:

| Call | `ru` output |
|------|-------------|
| `i18n.Number(ctx, 1234.5, 2)` | `1 234,50` |
| `i18n.Currency(ctx, 1234.5, "RUB")` | `1 234,50 ₽` |
| `i18n.Date(ctx, 2026-03-09)` | `09.03.2026` |
| `i18n.MonthYear(ctx, 2026-03-09)` | `Март 2026` |

The demo calendar's month navigation targets `/showcase/i18n/calendar/month`,
a fragment route that renders just the `CalendarMonth` element under the same
locale — so a prev/next/Today press swaps the calendar element and never
injects a full document. The locale is selected per rendered component; there
is no cookie, query parameter or middleware involved.

## Custom locale

A `Locale` is plain data. Register one in your own package's `init`:

```go
package app

import "github.com/fbv/go-templ-ui/view/i18n"

func init() {
	_ = i18n.Register(&i18n.Locale{
		Tag:  "de",
		Name: "Deutsch",
		Strings: map[string]string{
			i18n.KeyYes:    "Ja",
			i18n.KeyNo:     "Nein",
			i18n.KeyToday:  "Heute",
			"app.greeting": "Hallo, %s",
		},
		Months: [12]string{
			"Januar", "Februar", "März", "April", "Mai", "Juni",
			"Juli", "August", "September", "Oktober", "November", "Dezember",
		},
		Weekdays: [7]string{"Mo", "Di", "Mi", "Do", "Fr", "Sa", "So"},
		Numbers: i18n.NumberFormat{
			Decimal:      ",",
			Group:        ".",
			GroupSize:    3,
			PercentSpace: true,
			Currency: map[string]i18n.CurrencyFormat{
				"EUR": {Symbol: "€", Position: "after", Space: true, Decimals: 2},
			},
		},
		DateLayout:     "02.01.2006",
		DateTimeLayout: "02.01.2006 15:04",
		TimeLayout:     "15:04",
	})
}
```

Use it like any built-in locale:

```go
if de, ok := i18n.Get("de"); ok {
	ctx := i18n.WithLocale(ctx, de)
	i18n.T(ctx, "app.greeting", "Anna")   // Hallo, Anna
	i18n.Currency(ctx, 1234.5, "EUR")     // 1.234,50 €
	i18n.Percent(ctx, 12.5, 1)            // 12,5 %
}
```

Keys a custom locale leaves out resolve through `Default()`, so a partial catalog
is usable: translate what matters first and fill the rest in over time.
Registering an existing tag replaces that locale for the process. Registering a
locale under `"en"` replaces `Default()` and `T`'s fallback as well.

## Styles

Not applicable — the package renders no markup and owns no styling. It only
produces strings and formatted values that components place in their own
markup.

## Dark Mode

Not applicable — locale data is theme-independent.

## No hardcoded strings in components

User-facing strings in the migrated components resolve through `i18n.T`, so a
consumer can render those components in another language without forking it. A
new component must not ship a bare literal. Two kinds of labels are deliberately
outside the catalog, alongside each other: `CalendarTimeline`'s event-count
string (`%d событий`), which needs grammatical plural forms this package does
not provide; and the remaining out-of-scope labels the allowlist still carries —
tree `Toggle`, breadcrumb `Breadcrumb`, select_dialog/confirm_dialog `Close`, and
chat's `Введите сообщение...` placeholder.

`view/ui/hardcoded_strings_test.go` enforces this. It parses every
`view/ui/*.templ` with templ's own parser (`github.com/a-h/templ/parser/v2`) and
walks the AST, collecting:

- literal **text nodes** in templ bodies (`*parser.Text`); and
- the literal values of the user-facing attributes `aria-label`, `title`,
  `placeholder` and `alt` (`*parser.ConstantAttribute`).

Because templ's parser decides what is text, the extraction follows the templ
grammar rather than a re-implementation of it. Text inside `if`/`for`/`switch`
bodies is reached. An inline expression splits a text run: `Total { n } results`
reports `Total` and `results` and never the identifier `n`. A component call is
a call, not text: `Total` followed by `@Price()` reports `Total`. An `@` inside
text stays text: `support@example.com` is one node. A `<style>` block's contents
are raw and its braces cannot hide the markup after it. `{{ ... }}` statements,
`{...}` expressions, comments and `<script>`/`<style>` bodies never produce a
text node, and a literal is never classified by its words: `Warning:` (ending in
a colon) and `Assign with x := 1 in code` are reported. templ itself refuses a
bare text line that begins with `if`/`for`/`switch`, so such a literal cannot be
silently dropped — the file fails to parse — and the parseable spelling
(`{ "if" }` or an entity such as `&#105;f`) is what the guard sees.

The sorted `file: text` entries are compared with `view/ui/i18n_allowlist.txt`
as a multiset, duplicates included: a second copy of an already allowlisted
string is a new hardcoded string and fails. A mismatch fails the build and names
what to fix:

- an entry reported as **extra** is a hardcoded user-facing string — route it
  through `i18n.T(ctx, key)` instead of adding it to the allowlist;
- an entry reported as **stale** is no longer in the source — delete the line.

The allowlist holds only strings that are out of scope for this library's
migration (the components the showcase's i18n demo does not render) and
punctuation-only text nodes such as `,`, `—` and `&laquo;`, listed as they
appear. It is never extended: a new hardcoded string fails the build instead.

**What the guard covers and what it does not.** It reads `view/ui/*.templ`
source: literal text nodes and the four user-facing attributes above. It does
**not** see strings built in Go code that assembles markup or data (for example
labels concatenated in a `.go` file or a table in a `.go` file), and it does not
evaluate expressions: a string produced dynamically, or a Go string literal used
inside `{ ... }`, is invisible to it. It is a tripwire for the common case, not a
proof that every string is localized.

## Accessibility

- **Language of the document (WCAG 3.1.1).** `layout.Page` renders
  `<html lang="{ i18n.From(ctx).Tag }">`, so the tag of the selected locale
  becomes the document language. Assistive technology pronounces the page in the
  right language without any per-component work.
- **Language of parts (WCAG 3.1.2).** Strings resolved through `i18n.T` inherit
  the document language; an inline foreign-language span still needs its own
  `lang` attribute in your template.
- **Direction.** This package sets language only. RTL/`dir` is out of scope for
  this ticket: no component is mirrored, and existing physical spacing classes
  are unchanged.
- **Meaning never rests on words alone.** Keep the icon or text cue that
  accompanies a status in your own templates; translating a label does not
  replace it.
